busabunga.com

Type

Website build + technical SEO

Date

Launched June 2026

Role

Research, design, build, SEO

Client

PT Tjikko Sentral Industrial

A commercial site for Tjikko's decorative foam line, built end to end in React with Claude Code as the development partner. Keyword research, information architecture, build, content and search strategy were all mine. There was no existing site, no legacy traffic, no backlink profile and no advertising budget, so the only lever available was getting the structure and the search intent right before anything shipped.

What I built

  • Commercial keyword and intent research completed before any code was written
  • Information architecture organised around buyer intent rather than the internal product catalogue
  • Full React build, AI-assisted through Claude Code and Git
  • Technical SEO foundation: crawl paths, indexation rules, schema, Core Web Vitals
  • Dedicated pages for florists, wholesale buyers and private-label enquiries
  • WhatsApp-first enquiry flow, matching how Indonesian B2B buyers actually make contact
  • Search Console and analytics instrumented from day one, not retrofitted

The challenge

A brand-new domain competing for commercial terms that established suppliers and the big marketplaces already owned. No authority to borrow from, no history for Google to trust, and no paid support to buy time while rankings matured. On a domain like that, most of the usual SEO levers are unavailable: what is left is structure, intent matching, and not making the mistakes that keep new sites invisible.

How I approached it

I mapped the commercial keyword set first and let it decide the site architecture, which is the opposite of the usual order. Primary terms were floral foam, wet and dry floral foam, busa bunga and floral foam indonesia; secondary terms covered supplier, distributor, grosir and private-label variations. Each target term got exactly one page that clearly owned it, so the site never competed with itself. Buyer-intent language went into headings and body copy rather than internal product naming, and the enquiry path was kept short enough that arriving traffic had somewhere obvious to go.

Result

Within roughly one month of launch the site held #1 and page-one Google positions for its target commercial keywords. That came from structure and intent matching, not from authority the domain had not had time to build. It is the cleanest evidence I have that the method is repeatable: same approach, no inherited advantages, measurable outcome.

Stack

  • React
  • Claude Code
  • Technical SEO
  • Schema.org
  • Search Console
  • GA4
  • Cloudflare

Sekolah Trinitas

Type

Local SEO

Date

2026

Role

SEO & website developer

Client

Sekolah Trinitas — via RIAS Strategic

Local search work for a Christian trilingual school in Bandar Lampung, delivered through the RIAS Strategic freelance talent pool. The brief was easy to state and hard to win: own the terms parents type when they are shortlisting schools for their children.

What I built

  • Keyword mapping across the five priority local terms
  • On-page rewrite so each term had one page unambiguously earning it
  • Cannibalisation audit and fixes across overlapping pages
  • Technical clean-up: crawl paths, indexation, on-page structure
  • Local relevance signals tightened around Bandar Lampung
  • Rank tracking against the target set through to position

The challenge

Education keywords in a regional Indonesian market are crowded with directories, aggregators and institutions that have been online for a decade. Ranking meant beating pages with far more authority, on terms where realistically only the top result converts. Parents do not scroll for a school, and the decision cycle is short and emotional, so second place is close to worthless.

How I approached it

I rebuilt the on-page and technical foundation around the five keywords that mattered and made sure each had a single page earning it, which removed the cannibalisation quietly splitting the site's own relevance across near-duplicate pages. Local signals were tightened so the school read unambiguously as a Bandar Lampung institution rather than a generic national one. No link building was involved: the gains came from fixing what the site was already saying badly.

Result

#1 Google rankings for all five target keywords: sekolah kristen lampung, sekolah kristen terbaik lampung, sekolah trilingual terbaik lampung, sekolah trilingual lampung, and sekolah kristen lampung paling bagus. Verifiable in an incognito search from the region.

Hermes AI Agent System

Type

AI automation platform

Date

2026 — ongoing

Role

Architect & builder

Client

Self-hosted / internal

A self-hosted multi-agent system that does real daily work. Not a demo, not a prototype. Claude API handles the reasoning, n8n owns scheduling and orchestration, and MCP connects the whole thing to live WordPress sites and analytics properties. It runs on my own VPS, which means I also own the uptime, the credentials and the failure modes.

What I built

  • Multi-agent framework on a self-hosted VPS, with a reusable skill library
  • Claude API as the reasoning engine; Claude Code and Git as the development workflow
  • n8n for scheduling, orchestration, retries and error handling
  • Claude Desktop with MCP connected to live WordPress sites
  • RAG architecture for grounding agents in real documents rather than model memory
  • Full multi-page client website builds executed through MCP
  • SEO, GEO and AEO documentation systems
  • GA4 audits and a daily reporting agent across three properties

The challenge

Most AI automation stops at the proof-of-concept stage: impressive in a screenshot, unreliable the moment it has to run unattended against production systems. The hard part was never the model call. It is everything around it: scheduling, credential handling, retry logic, and knowing when the output is wrong before it reaches anyone who would act on it.

How I approached it

I built Hermes as infrastructure rather than as a collection of scripts. Agents are composable skills with a Git workflow behind them, so behaviour is versioned and reviewable. MCP handles the integrations into live systems so agents act through real interfaces instead of scraped ones. n8n owns scheduling and retries, which keeps the failure handling out of the prompts. The design bias throughout is towards systems that degrade visibly rather than silently.

Result

A GA4 Daily Reporter runs in production across three properties, pulling the data, formatting the report and distributing the insight without a human in the loop. The system is part of a 90-day practitioner sprint aimed at three to five production agents and a monetisable automation service.

  • MCP

Quotation vs PO Validation

Type

Business process automation

Date

Live since July 2026

Role

Architect & builder

Client

PT Tjikko Sentral Industrial

A first-line AI validation layer that checks incoming customer purchase orders against the quotations they came from. It is a small, unglamorous problem that quietly costs a lot: a mismatch caught after acceptance becomes a margin loss or an argument, and catching them by hand is exactly the kind of work that gets skipped when the week is busy.

What I built

  • Line-item validation: does the PO match what was actually quoted
  • Price validation: does the PO price match the quotation price
  • Expiry validation: was the quotation still valid when the PO arrived
  • Built on Claude scheduled tasks with MCP integrations into Google Drive and Gmail
  • Reports hourly, so a mismatch surfaces the same working day
  • Deliberately separate from Hermes, which is n8n-based: different failure modes, different operational risk

The challenge

Manual reconciliation is the sort of task that is important but never urgent, so it slips. It also has to be right: a validation layer that raises false alarms gets ignored within a week, and one that misses real mismatches is worse than nothing because it creates false confidence.

How I approached it

I kept the scope narrow on purpose. Three checks, clearly defined, running on a schedule rather than trying to be a general-purpose document agent. It reads from the systems the team already uses via MCP rather than asking anyone to change how they work, and reports hourly so a problem surfaces while the paperwork is still fresh. Building it separately from Hermes was a reliability decision, not a technical one: I did not want a workflow failure in one system to take out the other.

Result

Live in production since July 2026, removing a recurring manual reconciliation task from the Marketing Manager and returning that time to field and market work. It is still early, so there is deliberately no catch-rate or time-saved figure here: those numbers are worth having only once the system has a real track record behind it.

Stack

  • Claude API
  • Claude scheduled tasks
  • MCP
  • Google Drive
  • Gmail
